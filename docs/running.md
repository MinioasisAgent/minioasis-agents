# Running Minioasis

How to build, test, and run the application on a development machine. Keep this file current when a step changes.

## Prerequisites

- The .NET 10 SDK.
- No Koha server and no credentials. Tests never need either (`TS-008`).

## Run every check

```bash
bash scripts/preflight.sh
```

On Windows, run `pwsh scripts/preflight.ps1`. The script restores, checks formatting, runs the tests, and builds the API for publishing, as `docs/workflow/checks.md` describes.

## Build and test

```bash
dotnet build minioasis.slnx
dotnet test minioasis.slnx
```

Run the tests in a shell where no `MINIOASIS_KOHA_*` variable is set: the test host refuses to start if one is, so that no test can carry real Koha settings (`TS-008`).

The test projects use xUnit v3 through the VSTest runner, which is what `dotnet test minioasis.slnx` starts. They reference `xunit.v3.mtp-off`, the variant of xUnit v3 without Microsoft.Testing.Platform, because the .NET 10 SDK refuses to run a Microsoft.Testing.Platform project through VSTest. A test file needs `using Xunit;`.

Each test run prints a warning that `VSTEST_ARTIFACTS_DIRECTORY` was not found and that `Microsoft.NET.Test.Sdk` may be outdated. The package is the latest version; the warning comes from the SDK's bundled test platform and is harmless. Do not downgrade to silence it.

## Configure Koha

Minioasis reads its Koha settings from four environment variables when it starts (spec 001, R10 to R12):

| Variable | Required | Value |
| --- | --- | --- |
| `MINIOASIS_KOHA_BASE_URL` | yes | The absolute address of Koha's REST API, ending in `/api/v1`, for example `https://koha.example.org/api/v1`. A trailing slash is optional. It must use `https`; plain `http` is allowed only when `ASPNETCORE_ENVIRONMENT` is `Development`. No query string, fragment, or user information. |
| `MINIOASIS_KOHA_CLIENT_ID` | yes | The client id of the Koha API client of the service account. |
| `MINIOASIS_KOHA_CLIENT_SECRET` | yes | Its client secret. Never commit it (`EX-005`). |
| `MINIOASIS_KOHA_TIMEOUT_SECONDS` | no | The deadline for one Koha interaction, in whole seconds from 1 to 120. Default 10. |

If a variable is missing, blank, or invalid, Minioasis refuses to start, and the message names the variable without showing its value. Minioasis does not contact Koha when it starts, so a valid configuration starts even when Koha cannot be reached.

## Run the API

```bash
export MINIOASIS_KOHA_BASE_URL='https://koha.example.org/api/v1'
export MINIOASIS_KOHA_CLIENT_ID='…'
export MINIOASIS_KOHA_CLIENT_SECRET='…'
dotnet run --project Minioasis.Api
```

The API has no endpoints yet: every request is answered with 404 and the error body of spec 001 (code `not_found`, a `traceId`). It refuses to start when its error definitions and `Minioasis.Api/Resources/errors.en.json` disagree, and says which code is wrong. Nothing calls Koha yet, so any values that pass the checks above let it start.

## Generate a Koha client

Koha clients are generated by NSwag, pinned in `dotnet-tools.json`, from a focused contract in `contracts/` into `Minioasis.Koha/Generated/<Feature>/` (`EX-002`, `EX-003`). Never edit the generated files or `contracts/official_koha_openapi.json` by hand.

The OAuth token client, from `contracts/oauth.openapi.json`:

```bash
dotnet tool restore
dotnet nswag run nswag.json /variables:Contract=oauth,Feature=OAuth,FeatureSingular=OAuth
```

For another focused contract, `contracts/<name>.openapi.json`, set `Contract=<name>` and the feature's folder and type name in `Feature` and `FeatureSingular`. Regenerate only the client whose contract changed, inspect the generated diff, and commit the contract and the generated files together.
